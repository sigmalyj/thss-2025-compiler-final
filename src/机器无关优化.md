## 机器无关优化记录

- 目标：在 SysY 前端生成的自定义 IR 上做轻量机器无关优化，减少冗余计算，为后续后端准备更干净的 IR。
- 范围：当前实现包含生成阶段的简单折叠，以及独立的前向常量传播和无用代码删除（DCE）pass。
- 代码位置：优化入口在 [src/compiler/Optimizer.cpp](src/compiler/Optimizer.cpp)，在 IR 生成后由 [src/main.cpp](src/main.cpp) 调用 `runOptimizations`。

### 活跃变量分析（计划）
```cpp
// 逆向数据流：LIVE_out[B] = ⋃ LIVE_in[suc]
// LIVE_in[B] = (LIVE_out[B] - DEF[B]) ∪ USE[B]
struct LiveSetPass {
  using VarSet = std::unordered_set<Value*>;
  std::unordered_map<BasicBlock*, VarSet> in, out;

  void run(Function* f) {
    bool changed = true;
    while (changed) {
      changed = false;
      for (auto it = f->rbegin(); it != f->rend(); ++it) {
        auto* bb = it->get();
        VarSet newOut;
        for (auto* s : bb->successors()) newOut.merge(in[s]);
        VarSet newIn = newOut;
        for (auto* inst : bb->rev_instructions()) {
          // kill def
          if (inst->hasResult()) newIn.erase(inst);
          // add uses
          for (auto* op : collectOperands(inst)) newIn.insert(op);
        }
        if (newOut != out[bb] || newIn != in[bb]) {
          out[bb] = std::move(newOut);
          in[bb] = std::move(newIn);
          changed = true;
        }
      }
    }
  }
};
```
- 用途：识别活跃变量，后续结合 DCE 清除死存储、死定义。
- 状态：尚未落地，逻辑如上伪代码，可与现有 `collectOperands` 重用。

### IR 生成阶段的小折叠
- 在 IR 构建时对纯常量二元运算和部分代数等价（+0、*1、*0、/1 等）做即时折叠，见 [src/compiler/SysYIRGenerator.cpp](src/compiler/SysYIRGenerator.cpp) 中 `foldBinary`/`foldCmp`。
- 这些折叠只处理局部可判定的整数常量，不跨指令或基本块传播。

```cpp
Value* SysYIRGenerator::foldBinary(BinaryOp op, Value* lhs, Value* rhs) {
  if (bothConst(lhs, rhs)) return builder_.getInt32(eval(op, lhs, rhs));
  if (rhs == c0 && op == Add) return lhs;
  if (rhs == c1 && op == Mul) return lhs;
  if (rhs == c0 && op == Mul) return c0;
  if (rhs == c1 && op == SDiv) return lhs;
  if (lhs == c0 && op == Add) return rhs;
  if (lhs == c0 && op == Mul) return c0;
  if (lhs == c1 && op == Mul) return rhs;
  return builder_.createBinary(op, lhs, rhs);
}
```

### 前向常量传播（forward constant propagation）
- Pass 位于 [src/compiler/Optimizer.cpp](src/compiler/Optimizer.cpp) 的 `forwardConstPropagation`：
  - 维护一个 `Value* -> ConstantInt` 的映射，按基本块顺序遍历指令。
  - 在遍历时用已知常量替换操作数，覆盖 Binary、ICmp、ZExt、GEP、Br 条件、Ret 返回值等指令的操作数。
  - 对 Binary/ICmp/ZExt 若两侧（或输入）均为常量，立即计算结果并把当前指令记作常量，后续可继续传播。
  - Load/Store/Call 不做传播（保守处理副作用）；GEP 仅替换索引和值但不折叠地址计算。

```cpp
void forwardConstPropagation(Function* f) {
  ConstMap m;
  for (auto& bb : f->getBlocks()) {
    for (auto& iptr : bb->instructions()) {
      auto* inst = iptr.get();
      replaceOperandsWithConsts(inst, m);
      if (auto c = tryFoldToConst(inst)) {
        m[inst] = c; // 当前指令产出常量
      }
    }
  }
}
```

### 窥孔优化（peephole）
- 与 IR 生成耦合的微型折叠，快速消解局部冗余。

```cpp
Value* foldCmp(CmpOp op, Value* lhs, Value* rhs) {
  if (auto l = asConst(lhs); auto r = asConst(rhs)) {
    return builder_.getInt1(evalCmp(op, l, r));
  }
  // x == x  => true; x != x => false
  if (lhs == rhs) {
    if (op == CmpOp::EQ) return builder_.getInt1(1);
    if (op == CmpOp::NE) return builder_.getInt1(0);
  }
  return builder_.createICmp(op, lhs, rhs);
}
```

### 无用代码删除（dead code elimination）
- 同文件的 `deadCodeElimination`：
  - 先按指令收集操作数使用次数。
  - 将“有结果且无副作用”的指令视为可删除（Binary、ICmp、Alloca、Load、GEP、ZExt）。
  - 如果使用次数为 0，则删除该指令，并扣减其操作数的使用计数；采用循环直到不再变化，去除连锁冗余。

### 调用顺序
- `optimizeFunction` 先运行前向常量传播，再运行 DCE；`runOptimizations` 对每个非声明的函数执行。
- 主程序在生成 IR 后调用 `runOptimizations`，因此所有函数都会经过这两步清理。

### 后续改进方向
- 活跃变量分析与基于活跃性的 DCE，支持移除死存储和更激进的删除。
- 跨基本块的常量传播（需控制流图与到达定值/支配分析），避免仅顺序遍历的局限。
- 对 GEP/数组索引的常量折叠，以及条件分支上的常量条件简化（CFG 清理）。
- 增加回归测试并在优化后与无优化输出对比，确保语义保持。
